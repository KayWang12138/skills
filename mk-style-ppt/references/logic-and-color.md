# 逻辑与着色判例

用于分层技术材料，或用户指出“逻辑不清、颜色随机”时。三层结构来自 TileSim 案例，不强加给其他主题。

## 先建领域分类

先判断模块在表达对象、操作语义、性能模型还是执行约束，以及它与旁边模块是同级、父子还是调用关系，再分配颜色。

| 对象 | 本案例的归属 | 原因 |
| --- | --- | --- |
| Cube 吞吐、尾部修正函数 | 微架构模型 | 将硬件特征转成局部性能函数 |
| MMAD / VADD / Copy TileOp | TileOp | 计算与搬运均为操作语义及其代价模型 |
| load / store / 矩阵与向量操作组合 | TileOp | 同层操作片段，不能因操作性质不同拆层 |
| Task 映射、合法顺序、同步与容量阻塞 | 调度 | 决定工作位置、执行约束与时间线 |
| 张量形状、源码、统一 IR、输出数值 | 表示或参数 | 不必新增与三层并列的功能类别 |
| 带宽模型中的缓存容量 | 微架构或访存分析 | 与调度中的容量阻塞用途不同，不能只按“容量”一词分类 |

## 必须避免的分类

**“蓝色表示数据 / 表示 / 搬运 / 输出，绿色表示计算，棕色表示约束。”**

错误在于混合对象性质、流程角色和操作类型。搬运与计算在 TileOp 层并列，输入输出只是流程位置，不能据此解释架构。

**“第一列蓝、第二列绿、第三列棕，所以全篇有逻辑。”**

位置一致不等于概念一致。只有用户明确选择按位置编码，且页面同构时才可作布局规则；不要赋予虚假的功能含义。

**“调度页所有东西全棕，微架构页全蓝。”**

主题相同，不代表参数、引用的其他层模型、输出与背景都同类。按具体对象着色，不能按页批量换色。

## 本案例的可用映射

| 主分类 | 强调色 | 浅填充 | 正例 | 反例 |
| --- | --- | --- | --- | --- |
| 微架构性能模型 | 蓝灰 `#526E85` | `#E9EEF3` | Cube 函数、带宽函数、VF 性能调用、L2 模型 | load TileOp、普通张量 |
| TileOp 操作与组合 | 灰绿 `#667F75` | `#EAF0EC` | Copy、MMAD、VADD、复合 TileOp、原语序列 | 硬件标定函数、核映射 |
| 调度与执行约束 | 暖褐 `#927A64` | `#F1ECE6` | mapper、planner、依赖、资源等待、事件组装 | 普通输出时长、形状参数 |
| 中性内容 | 深 `#2D3338`、中 `#69737C`、浅 `#E3E7EA` | 白或统一浅灰 | 前端表示、参数、结果、大容器、普通表格 | 核心模型的层级标签 |

色号是沉稳配色的起点，不是所有材料必须遵循的品牌规范。

二级编码：TileOp 时间线搬运用较浅灰绿 `#9AAFA4`，计算用较深灰绿 `#667F75`，行标签写明 MTE、Cube、VEC。两者同属 TileOp，不用不同色相暗示不同层。同类活动跨页维持规则。

数据曲线可独立编码 FP16 / FP32、核数或数据量，依据本图图例解释。不要将其系列含义塞进架构颜色表。

## 最小页面计划

工作材料中简短记录：本页问题与摘要、前后页关系、同级模块的分类依据、主图对象和阅读方向、证据口径、各色块类别与混合容器处理。不必强制向用户输出这份记录。

若写不出分类依据，先改模块组织，不能靠加标题、加色块和加箭头掩盖。
