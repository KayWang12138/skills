# MK Style PPT

这是技术演示文稿的内容与视觉决策规范，不是某个项目的固定模板。目标是让读者看清系统如何工作、各部分为何这样组织、结论来自哪些证据。**内容逻辑、排版逻辑、着色逻辑是前三项硬性质量门槛**，不能靠视觉修饰或提高密度替代。

用户本次明确要求及提供的模板优先。默认中文学术风格，表达克制，必要英文术语和缩写保留。不要把大量工程字段、代码标识符或实现细节当作技术深度。

## 配合其他能力

- 制作或修改 PPT 时同时使用当前可用的 `presentations` skill，遵守其制作、可编辑对象、渲染和交付流程。本 skill 负责风格与内容决策。
- 生成配图时使用当前可用的 `imagegen` skill。行业惯例、论文和技术概念需要调研时，先查可信原始来源再绘制或生成。
- 不依赖某个工程、固定版本路径或本轮对话。下述默认值可以被用户针对具体项目的要求覆盖。

## 1. 内容逻辑：先建立概念关系

制作前在工作材料中建立页面纲要。每页明确：**本页问题、核心结论、所属层级、所需证据、与前后页的承接**。不必为此等待批准，除非用户明确要求先汇报。

- 全篇通常从总体到局部、从输入到处理再到结果。存在明确前后端时沿技术路径展开，避免在不同抽象层来回跳转。
- 页内通常从上层决策到下层机制，从概念到求值或实例。区分依赖、调用和结果返回方向，不混用箭头。
- 同级并列模块使用同一分类依据、同一抽象粒度。父子项、流程位置和操作类型不能因为凑版面而并列。
- 按领域含义分类，不能仅凭关键词。例如“Cube 性能函数”和“Cube TileOp”代表不同层的对象。
- 实现现状、设计接口、待补充内容和理论假设明确区分。压缩页面不能抹掉这些边界。
- 页数服从叙事及用户要求，默认不增加纯标题页，合并重复内容，保留明确要求的空白预留页。不要为压缩页数牺牲可读性。

复杂分类与配色争议时，阅读 [逻辑与着色判例](references/logic-and-color.md)。案例只作判断依据，不将某个项目的三层架构强加给其他主题。

## 2. 排版逻辑：顶部讲思路，下方按主题展开

默认横向 16:9。总体架构、完整时间线等适合一幅主图的页面可以整体构图。其余解释页优先采用：

**标题 → 顶部一至两行思路或结论 → 下方若干并列竖向主题列 → 必要来源或口径说明。**

- 顶部描述本页建模思路、因果关系、结果或适用边界。不要只写“左图是什么、右表是什么”，不要放制作备注或纯图例。
- 两点明确分两行，避免做成两个左右并列的小摘要框。每行加粗一个短的重点，正文常规字重，不能整行全粗。
- 每个主题列依次安排主题名称、简短解释、核心图、证据或实例，对齐标题与主要内容基线。
- 列数依概念和可读性选择，常见 2–4 列，不固定三列。不能将不同层级概念拼在一起凑列数。
- 并列主题应可比较；连续步骤应明确顺序。分类对照不要随意连箭头，因果步骤不要只靠摆放位置暗示关系。
- 使用白底、中性大容器、细分隔线和稳定间距。避免整页铺色、仪表盘式碎卡片堆叠和每页更换主色。

## 3. 信息密度：增加有效信息，不堆字

默认紧凑且内容充分，适合技术读者细看。密度来自机制、关系、约束、公式、实例和证据，不来自重复文字、装饰或一味缩小字号。

- 常规解释页尽量结合解释、主图和有意义的证据，按内容选择表格、曲线、时间线、公式或代码。不机械要求每页凑齐图、表、文字三件套。
- 主图解释关系，表格支撑判断，文字补足边界，三者不重复同一组词。
- 框架图展示必要对象、分层边界、接口、连接含义、数据或控制路径和重要约束。增加层次服务于解释，不靠多画方框装深度。
- 代码展示一段足以说明真实能力的逻辑，标记分块、分配、搬运、计算或同步等关键处，避免只有一行玩具示例，也避免整页源码。
- 稀疏页面先补机制、实例或证据，再压缩空白。要求“密度翻倍”指有效内容，不是把文字量翻倍。

## 4. 着色逻辑：先分类，后填充

**每个非中性色都须有明确的类别或关系含义，不能先填色再补解释。** 在工作材料中建立颜色映射：类别、抽象层级、色号、正例、反例、跨页使用位置。

- 选择领域中稳定的架构层级或功能类型作为主分类轴，不把层级、阶段、对象状态和输入输出混成一张颜色表。
- 同时表达层级和类型时，用清晰的双重编码，例如色相表示层级，深浅或线型表示层内类型。二级编码不能改变主色含义。
- 同一概念跨页同色。相同颜色不能前页代表计算，后页代表输入，再后页代表同步。
- 参数、普通表示、结果摘要、表头和大容器通常使用中性色，不必为每种东西新增颜色。
- 层级色落在相应小模块、细线或标签上，不铺满整页。包含多类对象的父容器优先中性，子节点分别编码。
- 搬运、计算等类型是否同层，要依据项目语义确定。例如 TileSim 中两者均属于 TileOp，不能因操作性质不同而误拆为不同层。
- 默认 2–3 种低饱和强调色，选沉稳色调。灰色控制为深、中、浅约三档，加白底，避免过多灰度。
- 定量曲线可以独立用颜色编码数据系列，须有本图图例；重复系列跨图一致。曲线图例不能冒充架构层级颜色。
- 品牌要求优先，查官方规范。品牌红可作小面积强调，不等于满篇红白，也不能破坏语义映射。
- 示意图片保留合理彩色，不为统一原生图配色而全部灰度化。图片材料色与原生语义编码应有清楚边界。
- 禁止按关键词、列次序或整页主题批量着色后宣称有语义一致性。具体判例见参考文件。

## 5. 数据支撑：先核实，再放图表

- 查用户材料、仓库测试、benchmark、PR / commit 与实验记录。代码公式能证明模型定义，不能自动证明精度。
- 表格优先放可比较的数值、单位、条件与结论相关字段，不用“模块 / 功能 / 优点”的泛表格充数。
- 精度数据保留样本数、指标定义、硬件配置、测试对象、版本或历史口径。原语误差不能冒充完整 API 或端到端误差。
- 对比数据需要可比配置。不同硬件或配置可以并置，但须明确标注，不能伪装为同条件验证。
- 图表回答实际问题，标出轴、单位、系列、条件；有意义时加入多系列、拐点或误差分布。不要只放孤立无含义的曲线。
- 明确区分实测、模型预测、理论推导、教学示例与假设数据。缺数据就标待验证，不虚构数字，不把示意曲线当结果。
- 来源记录到相应页面，关键条件和影响结论的假设需读者可见，不能全部藏在备注。

## 6. 框架图与示意图互补

框架图解释结构、流程和约束；示意图建立直觉、解释物理关系和实例。先判断缺少哪一种解释，再选择视觉。

- 精确架构、流程、核映射、时间线、表格与数据图保持原生可编辑。用户要求拆成组件时保留原图布局、连线和外观。
- 抽象机制先调研业界惯例、论文图和技术文档，再制作原创示意或生成图片。例如核分配用工作网格与核组对应，数据复用用访问序列、复用距离和缓存驻留。
- 生成图片只作机制演示，不作测量结果、精确论文复现或数据证据。科学关系错误时必须修正，不能以视觉效果替代正确性。
- 一页通常一幅主图，可配小幅直觉例子。全篇扫描连续框图页，在认知收益明确的位置加示意，不每页都生成，不到处放装饰。
- 生成图少字，关键标签、数值、公式和连接尽量留在 PPT 内编辑。主图与小示意通过相同对象名或简短引导对应。
- 调研、生成与数据口径细则见 [图示与证据规范](references/visuals-and-evidence.md)。

## 7. 字体与字号

默认全部微软雅黑（Microsoft YaHei），覆盖中文、英文、表格、图例和代码；用户另有要求时按用户要求。以 pt 为准，注意工具换算：**12 pt = 16 px**。

| 内容 | 默认字号 | 使用方式 |
| --- | --- | --- |
| 页面标题 | 24–28 pt | 简明主题，避免两行 |
| 列或模块标题 | 15–18 pt | 明确层级 |
| 顶部摘要、主要描述 | 12 pt | 两点分两行，短重点加粗 |
| 图内标签、表格正文 | 10–12 pt | 正常阅读可辨认 |
| 代码、来源、次要说明 | 8–10 pt | 局部需要时使用，不让整页都是小字 |

字号层级全篇稳定。溢出时先精简措辞、合并重复信息和调整布局，再局部缩字。远距离演讲场景适当放大或拆页，不将高密度默认误用于所有场景。

## 8. 交付前的逻辑审阅

完成制作 skill 所要求的渲染、数据与可编辑性检查之外，逐项检查：

1. **内容**：标题和摘要能否串起论证？模块是否同级？机制、实现状态与结论是否对应？
2. **排版**：阅读顺序是否清楚？并列列是否可比？主图是否承担解释？两点摘要是否分两行？
3. **颜色**：每个有色块能否说明所属类别及跨页一致性？是否误拆同层类型？混合父容器是否误用单色？
4. **证据**：数值有无来源、单位和条件？曲线是否回答问题？历史验证、模型预测和教学示例是否混淆？
5. **图示**：是否连续多页都是框图？配图是否准确且形象？是否为统一颜色把彩色示意变灰？
6. **可读性**：描述是否以约 12 pt 为主？是否整页单色、过多灰度、过小图例、拥挤或溢出？
7. **Office 兼容性**：能渲染、能解压或制作工具能重新导入，不等于 Office 能正确打开。原生对象移植或直接修改 OOXML 后，必须检查结构顺序、对象 ID、关系引用与目标部件。交付前运行本 skill 的结构检查器，并按 [Office 兼容性与修复](references/office-compatibility.md) 完成适用检查；有 Office 环境时实际打开复验，无该环境时明确验证范围。

逻辑未解决时回到分类和页面目标，不仅换色、对齐或加箭头。交付完整结果，简述有影响的取舍，不输出冗长制作日志。
